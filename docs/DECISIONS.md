# Decisions

## 2026-08-24 — أداة تحرير PDF (طبقة فوق الصفحة)

- **الطلب:** أداة تعديل: حقول نص منسّقة في أي موضع، رسم يدوي، صور مع تدوير/تحجيم، وأشكال هندسية ملونة.
- **القرار:** أداة جديدة معزولة `edit` («تحرير») لملف PDF واحد. طبقات تُرسم فوق الصفحة ثم تُدمج (`flatten`) عبر pdf-lib — مثل التوقيع. **لا تعديل للنص الأصلي داخل الـ PDF** ولا حقول AcroForm. النص العربي PNG؛ الأشكال والحبر متجهات. التوقيع يبقى Fill & Sign منفصلاً.
- **التأثير:** `assets/js/tools/edit/*`، ربط في `main.js` و`capture.js` و`index.html`، أيقونة `#icon-edit`. بلا اعتمادات npm جديدة.
- **بأمر:** المستخدم (مالك المشروع).

## 2026-08-24 — معاملة الحاويات كأوراق (ظلال وحواف) — خلاف صريح لقاعدة DESIGN.md المسطحة

- **الطلب:** «تعامل الحاويات كأنها ورق يعني الظلال الحواف وكده».
- **القرار:** مخالفة مقصودة لقاعدة الارتداد المسطح في DESIGN.md («Sheet / drop / buttons: none») بأمر المالك. أُضيف مفردات ظل ورقية ناعمة (offset+blur بلا هالات): `--shadow-pad` للحاويات الصغيرة (فيلدست، قراءات، ملاحظات، معاينات، لوحة الماسح، بطاقات الملفات) و`--shadow-paper` لأوراق الإفلات (`#hub-drop` و`.intake` عند السحب/التحويم). الوضع الداكن له قيم أقوى. الأزرار وشريطا العنوان/الحالة يبقيان مسطحين بشعرات 1px.
- **التأثير المتوقع:** بصري فقط في `assets/css/app.css` عبر متغيري ظل جديدين؛ لا سلوك ولا IDs.
- **بأمر:** المستخدم (مالك المشروع). DESIGN.md نفسه لم يُعدَّل.

## 2026-08-24 — ريسكن بصري «ورقة مسطّرة وحبر أزرق» + توسيع لتحسينات UX في الحاويات

- **الطلب:** تنفيذ DESIGN.md حرفيًا (استبدال عالم الأوريجامي/صور الورق بورقة مسطّرة CSS + حبر أزرق + زر تنفيذ أحمر مسطح، وحذف `<img class="sheet-photo">`). ثم أمر صريح من المستخدم بالتوسّع: تعديلات في الواجهة وأماكن العناصر «حسب الحاجة وتجربة المستخدم»، وليس التوكِنز فقط.
- **القرار:**
  1. استبدال كل الخامات المصوّرة بتدرّج CSS دورة 28px (`repeating-linear-gradient`) على body/board/sheet، ووضع داكن بنفس النظام تحت `data-theme="blueprint"`.
  2. حاوية الرفع `#hub-drop` تصبح «كراسة مربعات»: شبكة مربعات CSS (خانات 20px بخطوط حبر شفافة) على سطح شبه ساد + حدود حبر 1px — برمجيًا بالكامل، بلا صور. نفس اللغة لباقي `intake`.
  3. لوحات الخيارات/القوائم/القراءات/التوست/بروجريس أسطح سادة (surface-1) بحدود شعرية لتظهر محتوياتها بوضوح فوق الورقة المسطّرة دون زحمة.
  4. الأداة الحالية في التايتل بار: خط تحت أحمر 2px بدل الشريحة الممتلئة (عبر `.legend__row.btn--act[aria-current]`).
  5. إصلاحات UX مصغرة: التوستات لم تعد تغطي شريط الحالة (ترتفع 52px+safe-area، وتعود للزاوية في شاشة البداية)، إخفاء سكرول‌بار قائمة الأدوات، تسميات الحقول بلون حبر أغمق للتباين (AA).
- **الممنوعات المحفوظة:** لا لمس لأي JS أو electron؛ كل الـ IDs كما هي؛ بلا سايد بار/شبكة بطاقات/ستيبر؛ بلا خطوط CDN أو ملفات فونت جديدة؛ بلا `url(...)` في الأنماط.
- **التأثير المتوقع:** تغيير بصري فقط داخل `assets/css/app.css` و`index.html` (حذف صورتي الرفع وتحديث تعليق DIRECTION CONTRACT). لا تغيير في السلوك أو الأدوات أو المسارات.
- **بأمر:** المستخدم (مالك المشروع) — التوسّع عن «ريسكن التوكنز فقط» صراحة في المحادثة.

## 2026-08-24 — Lumen Glow v2: إنضاج Aurora الأصلي (أبيض/أسود + جلو واحد) وإعادة تصميم شاملة

- **الطلب:** «ابحث في الإصدارات السابقة لما كان مجرد صفحة واحدة ... كان فيه جلو وأبيض للفاتح وأسود للداكن وكان جلو بسيط ... استخرج نظام التصميم القديم في وثائق منفصلة ثم طوّره وانضجه ثم طبّق النظام الجديد على التطبيق بالكامل مع إعادة تصميم من الصفر لكل شاشة».
- **الاستخراج:** الكوميت `58677f4` هو الأصل (أول صفحة واحدة بـ Aurora: `aurora-blob ×3` + `glass-panel` + `blur 24–32px` + `accent-glow 0.4` + `Cairo/Inter` + `pill nav`). وُثّق حرفيًا في `docs/design-aurora-legacy.md` (توكنز، خلفية، هاب، أزرار، قوائم).
- **الإنضاج (Lumen v2):** حُفظ الجوهر «أبيض نقي/أسود نقي + جلو بسيط» وحُلّت عيوبه: قوس قزح 3 ألوان → لون واحد Indigo، `blur 32/180%` → `20/160%` للأداء، `32px + -8px scale` → `28px + -4px` للانضباط، `opacity 0.45 فاتح 0.25` → `0.16` لتباين AA. وُثّق في `docs/design-system-lumen.md` وتم اعتماده في `DESIGN.md` الجديد (Lumen tokens).
- **التطبيق الشامل:** `assets/css/app.css` أُعيد كتابته من الصفر (348 كتلة، لا ورق/صور، زجاج خفيف)، `index.html` أُضيف له `aurora` + `glass-noise` وحُدّث `DIRECTION CONTRACT`، كل الشاشات (`view-start` الهيرو + 14 أداة) تستخدم نفس شبكة `glass-panel`، أزرار `pill accent` واحدة للتنفيذ، `docrow` خطي 36×56، و`titleblock` زجاجي سفلي. الـ IDs والـ JS كما هي — تغيير بصري فقط.
- **الأثر:** واجهة أهدأ وأخف (هالتان بدل 3)، تباين أعلى في الفاتح (`slate-900` على `0.72`)، لا اعتماد على صور، `prefers-reduced-motion` محفوظ. المرجعان المنفصلان يمنعان ضياع الأصل.

## 2026-08-24 — نشر على الويب + إصدارات تلقائية + تحديثات للمستخدمين

- **الطلب:** صفحة هبوط تُنشر على الويب بروابط تنزيل، إصدارات تلقائية عند كل push/tag، وقناة تحديثات تلقائية للمستخدمين المثبّتين.
- **القرار:**
  1. صفحة هبوط ثابتة في `landing/` تُنشر على GitHub Pages (workflow: `.github/workflows/pages.yml`) — بدون أي خدمات خارجية.
  2. إصدارات تلقائية عبر GitHub Actions عند دفع tag بصيغة `v*` (workflow: `.github/workflows/release.yml`) — بناء ويندوز (NSIS + Portable) ولينكس (AppImage) ونشرها على GitHub Releases.
  3. تحديثات تلقائية عبر `electron-updater` بمزوّد GitHub — تُفعّل في النسخ المثبّتة فقط (`app.isPackaged`)، تنزيل صامت ثم سؤال المستخدم عن إعادة التشغيل، وتثبيت عند الإغلاق كخيار احتياطي. النسخة المحمولة لا تُحدَّث ذاتيًا (سلوك electron-updater الطبيعي).
- **التأثير:** النشر يتطلب رفع الكود إلى `github.com/AHKH3/pdf-studio` وتمكين GitHub Pages من الفرع `gh-pages` (أو مصدر workflow). أول إصدار يبدأ بدفع tag مثل `v1.0.1`. حجم الحزمة سيزداد قليلًا بحزمة `electron-updater`.
