# فجوات PDF Studio مقابل المنافسين

بحث بتاريخ **13 أغسطس 2026**. المصادر: صفحات الأدوات الرسمية لـ iLovePDF و Smallpdf و PDF24 و Sejda و Adobe Acrobat Online و ILoveIMG و CamScanner و PDFgear و UPDF، مقابل شيفرة التطبيق الحالي (`assets/js/tools/*`, `index.html`, `PRODUCT.md`, `package.json`).

معايير التوصية: محلي 100٪، بدون حساب وبدون باي وول، سطح مكتب Electron، بدون كاميرا حيّة، وبدون مسار سحابي إن لم يوجد بديل أوفلاين واقعي.

---

## 1. ما نملكه اليوم

تسع عمليات ظاهرة في الفهرس، كلها تعمل في الرندرر على الجهاز:

| الأداة | ماذا تفعل فعلياً |
|---|---|
| **مسح مستند من صورة** | صور موجودة مسبقاً (JPG/PNG/WEBP) → كشف حواف OpenCV، تصحيح منظور، أوضاع ملوّن/حاد/رمادي/أبيض-أسود/أصلي، تدوير، تصدير PDF أو صور |
| **صور إلى PDF** | ترتيب، مقاس A4/Letter/حسب الصورة، هوامش، اتجاه |
| **دمج ملفات** | عدة PDF بترتيب قابل للسحب |
| **ترتيب الصفحات** | إعادة ترتيب، تدوير 90°، حذف، إدراج PDF أو صورة |
| **تقسيم واستخراج** | نطاقات، كل N صفحات، صفحة=ملف، استخراج في ملف واحد + ZIP عند الحاجة |
| **ضغط الملف** | إعادة ضغط صور XObject مع الإبقاء على النص؛ ومسار اختياري يعيد رسم الصفحة كـ JPEG للمستندات المصوّرة |
| **علامة مائية** | نص فقط (يُرسم كصورة لدعم العربية) |
| **ترقيم الصفحات** | أنماط منها `صفحة N`، مواضع بما فيها هامش خارجي متناوب |
| **PDF إلى صور** | PNG/JPG بمضاعف دقة، مجلد أو ZIP |

البنية: Electron 34، `pdf-lib` 1.17.1، `pdfjs-dist` 3.11.174، OpenCV.js مضمّن، Sortable. لا تشفير في `pdf-lib`. لا HEIC في قبول الصور. لا قارئ PDF مستقل، لا طابعة افتراضية.

هذا يكفي كـ «مجموعة أدوات يومية»، لكنه أقصر من شبكة iLovePDF/Sejda/PDF24 في: التوقيع، الحماية، OCR، الاقتصاص، واستخراج الصور المضمّنة.

## 2. قائمة الفجوات

الترتيب حسب أثر المستخدم العربي اليومي × قابلية التنفيذ أوفلاين. «وحدة جديدة» = شاشة/أداة مستقلة في الفهرس. «تحسين» = توسيع أداة موجودة دون شاشة جديدة.

### P0 — يستحق الشحن أولاً

#### توقيع محلي (Fill & Sign)

- **المنافسون:** Adobe Acrobat Online، Smallpdf، Sejda، iLovePDF (Sign)، PDF24، PDFgear، CamScanner
- **لماذا يهم:** معظم الأوراق المصرية (عقود، إيصالات، استمارات) تحتاج توقيعاً وختم تاريخ، لا دمج صفحات. هذا أكثر سبب يدفع الناس لرفع الملف إلى موقع.
- **أوفلاين:** عالٍ. رسم على canvas أو رفع صورة PNG شفافة أو كتابة الاسم بخط Zain، ثم `pdf-lib.drawImage` / `drawText` على الصفحة مع سحب الموضع. بدون طلب توقيع عبر البريد وبدون شهادات PKI.
- **النوع:** وحدة جديدة `sign`
- **حدود النسخة الأولى:** ختم توقيع + تاريخ + مربع نص حر. ليس محرّر AcroForm وليس Adobe Sign.

#### OCR عربي/إنجليزي → PDF قابل للبحث

- **المنافسون:** iLovePDF، Smallpdf (Pro)، PDF24 Creator (Tesseract محلي)، Sejda، CamScanner، PDFgear، UPDF
- **لماذا يهم:** ناتج المسح عندنا صورة بلا طبقة نص. المستخدم لا يستطيع نسخ رقم قومي أو البحث داخل الملف. هذا الفارق الأكبر مقابل كام سكانر بعد تجاوز الكاميرا الحيّة.
- **أوفلاين:** واقعي. **Tesseract.js** (WASM) مع ملفات `ara` + `eng` من `tessdata_fast` تُضمَّن في `assets/vendor` (لا CDN). المسار: pdf.js يرسم الصفحة → العامل يتعرّف → `pdf-lib` يضع الكلمات بشفافية 0 فوق الصورة. حجم تقريبي: نواة WASM ~5–8 MB + نماذج سريعة بضعة MB.
- **النوع:** وحدة جديدة `ocr`
- **صدق الجودة:** مطبوع عربي واضح = مقبول. خط يد وصور مظلمة = ضعيف. ترتيب RTL في الطبقة الخفية يحتاج اختباراً صريحاً (مربعات الكلمات لا الاعتماد على السطر الكامل). ليس بديلاً لـ Acrobat OCR.

#### حماية بكلمة سر / فك الحماية (بمفتاح معروف)

- **المنافسون:** iLovePDF، Smallpdf، PDF24، Sejda، Adobe Acrobat Online، PDFgear
- **لماذا يهم:** إرسال عقد أو بطاقة عبر واتساب. `PRODUCT.md` يؤجّل التشفير لأن `pdf-lib` لا يشفّر.
- **أوفلاين:** واقعي عبر **`@neslinesli93/qpdf-wasm`** (نفس محرّك PDF24 تقريباً): AES-256 للغلق، و`--decrypt` مع كلمة المستخدم للفتح. فك حماية بدون كلمة السر غير ممكن ولا يُعرض.
- **النوع:** وحدة جديدة `protect` (تبويبان: حماية / إزالة الحماية)
- **ليس:** شهادات، DRM، Adobe policy server.

#### اقتصاص الصفحات (Crop)

- **المنافسون:** iLovePDF، Smallpdf، Sejda، PDF24، Adobe
- **لماذا يهم:** هوامش ماسحة، إعلانات في رأس المحاضرة، قصّ بطاقة من صفحة A4. المسح عندنا يقصّ الصورة قبل PDF؛ لا قصّ لملف PDF جاهز.
- **أوفلاين:** عالٍ. معاينة صفحة + مستطيل، ثم `setCropBox` / `setMediaBox` في pdf-lib، مع خيار «هذه الصفحة / الكل». قصّ حقيقي للمحتوى (لا مجرد CropBox يخفيه Acrobat) اختياري لاحق عبر إعادة الرسم.
- **النوع:** وحدة جديدة `crop`

#### استخراج الصور المضمّنة

- **المنافسون:** iLovePDF (PDF→JPG فيه خيار استخراج)، PDF24، Sejda، Smallpdf
- **لماذا يهم:** مختلف تماماً عن «PDF إلى صور» عندنا (رسم الصفحة كاملة). هنا نخرج الشعارات والصور الأصلية بجودتها، لا لقطة الصفحة.
- **أوفلاين:** عالٍ. pdf.js `getOperatorList` + `paintImageXObject` / JPEG، ثم ZIP الموجود أصلاً في `assets/js/lib/zip.js`.
- **النوع:** وحدة جديدة `extract-images`

#### ضغط يحافظ على النص *(تحسين لأداة موجودة — ليست وحدة جديدة)*

- **المنافسون:** iLovePDF، Smallpdf، PDF24، Sejda
- **لماذا يهم:** الضغط السابق كان يحوّل كل صفحة لصورة فيقتل البحث والنسخ. للمستخدم الذي يضغط تقريراً نصياً هذه خسارة فادحة.
- **أوفلاين:** نُفِّذ (AHK-15). الافتراضي يعيد ضغط صور XObject عبر canvas (jpegify) ويترك النص والمتجهات؛ المسار القديم بقي خياراً «مثل المسح الضوئي». الحجم قبل/بعد يظهر في لوحة القراءة.
- **النوع:** تحسين `compress.js`

## 3. ترتيب التنفيذ المقترح

كل بند وحدة مستقلة تُشحن وحدها (شاشة + ملف أداة + بدون اعتماد على الوحدات التالية).

1. **توقيع محلي (`sign`)** — أعلى تكرار يومي، لا تبعيات WASM جديدة، نفس نمط العلامة المائية.
2. **حماية / فك حماية (`protect`)** — يضيف qpdf-wasm مرة واحدة ويُعاد استخدامه لاحقاً (إصلاح، linearize).
3. **اقتصاص (`crop`)** — pdf-lib فقط، معاينة موجودة (`preview.js`).
4. **استخراج الصور المضمّنة (`extract-images`)** — pdf.js موجود، ZIP موجود.
5. **OCR قابل للبحث (`ocr`)** — أكبر أثر بعد المسح، وأثقل (WASM + نماذج عربية). يُشحن بعد أن تستقر وحدات أخف حتى لا يتجمّد الإصدار على نموذج OCR.

بعد هذه الخمسة، بدون تداخل معها: علامة مائية بصورة، ثم PDF→نص، ثم deskew، ثم HEIC.

لا تُسند «ملء النماذج» و«التوقيع» لنفس الوكيل. لا تُسند «PDF إلى صور» و«استخراج الصور» لنفس الوكيل. لا تُسند «OCR» و«PDF إلى نص» لنفس الوكيل (مساران مختلفان: صور مقابل طبقة نص موجودة).

## 4. ما لا ننسخه

صراحةً خارج النطاق — حتى لو المنافس يعرضه في الصفحة الأولى:

- **كاميرا حيّة / مسح فوري** — مُستبعد بقرار المنتج. المسح من ملف موجود كافٍ.
- **طلب توقيع سحابي** (Adobe Sign، Sign.com، روابط البريد) — يحتاج خادماً.
- **OCR سحابي / Acrobat Sensei / CamScanner cloud OCR** — إن لم يُمرَّر عبر Tesseract المحلي أعلاه.
- **ذكاء اصطناعي: تلخيص، ترجمة، محادثة مع PDF، أسئلة، خريطة ذهنية** — iLovePDF و Smallpdf و UPDF و PDFgear Copilot. كلها APIs.
- **تحويل Office عالي الجودة** (PDF↔Word/Excel/PPT) — محرّكات Adobe/Sejda السحابية. أوفلاين صادق = LibreOffice كامل (~300 MB) كاعتماد خارجي، لا يُضمَّن في تطبيق مجاني خفيف. mammoth.js وdocx رديئان للتخطيط العربي. لا يُوعد به.
- **رفع دقة الصور بالذكاء** (ILoveIMG Upscale) — نموذج سحابي أو أوزان ضخمة.
- **حساب، مزامنة سحابية، Drive/Dropbox، فريق، سير عمل** — ضد «الملف لا يغادر الجهاز».
- **حدود مجانية / باي وول / علامات مائية قسرية على الناتج** — ضد مبدأ المنتج.
- **DRM، سياسة Adobe، تشفير بشهادة، إدارة حقوق المؤسسات**.
- **فاكس، طباعة سحابية، مشاركة برابط**.
- **مولّد ميمز، HTML إلى صورة كمنتج مستقل** (ILoveIMG).
- **تحرير النص الموجود كوورد** (PDFgear/UPDF/Acrobat Edit) — إعادة كتابة content streams غير موثوقة بـ pdf-lib؛ النسخة الصادقة هي «إضافة نص فوق الصفحة» ضمن التوقيع/التعليق.
- **كسر كلمة سر مجهولة** — غير قانوني وغير ممكن عملياً على AES.
- **XFA / نماذج Adobe الحية**.
- **مقارنة «نص قانوني» مع تتبع تغييرات** بمستوى Acrobat — الفرق البصري P2 يكفي إن لزم.
